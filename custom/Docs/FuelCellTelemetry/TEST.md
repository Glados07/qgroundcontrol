## 第一部分 · 测试计划

### 1. 准备与执行顺序

1. 先在 Qt 测试中验证轮询、来源校验、坏帧丢弃及端点切换。
2. 启动 QGC，检查设置项、输入校验和重启后的保存结果。
3. 在地面联调时启用盒子新版记录器的 `request` 模式，接入控制器并确认 QGC 已识别活动车辆，再验证回包及面板显示。

### 2. 用例与判定

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| FT-01 | 新配置启动 QGC，打开「应用设置 → 数传 → 燃料电池遥测」 | 默认显示 `192.168.144.110` 和 `14602` |
| FT-02 | 输入无效地址、端口 0 或 65536 | 界面提示错误，保留上一个有效值 |
| FT-03 | 保存新的合法地址和端口，重启 QGC | 两项设置保留 |
| FT-04 | 收到旧盒子读数后，切换到新端点 | 旧读数清空，新端点收到请求，旧端点回包不更新读数 |
| FT-05 | 注入坏校验包，或来自其他端口的回包 | 无效回包不刷新测量值 |
| FT-06 | 停止提供新样本约 2 秒，再恢复有效回包 | 显示占位符，恢复后重新显示读数 |
| FT-07 | 用实际盒子修改端点后重新取数 | 盒子回传 61002，面板显示与同一时刻的回包字段一致 |

### 3. 自动化测试入口

在配置为 Debug 的 Linux QGC 构建目录中编译并运行 `FuelCellControllerManagerTest`。

```sh
cmake --build <构建目录> --target FuelCellControllerManagerTest
<构建目录>/Debug/FuelCellControllerManagerTest -o -,txt
```

该测试目标同时覆盖 FCS 控制和盒子遥测。端点测试函数为 `requestsTelemetryAndAcceptsOnlyValidBoxReplies`。
